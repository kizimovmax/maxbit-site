# README_DEPLOY_WEBHOST1 — установка сборки MAXBIT 2.2 на dev.maxbitpro.ru

Цель: установить тему и модуль на **уже существующий** WordPress в `www/dev.maxbitpro.ru` (Webhost1 / ISPmanager, PHP 8.3, MySQL 8.0), наполнить тестовым содержанием и получить закрытый стенд. Базу данных, `wp-config.php` и уже имеющееся содержание не перезаписываем. DNS/HTTPS делает поддержка Webhost1. Публичный выпуск не входит.

Что нужно иметь под рукой: доступ в ISPmanager, логин/пароль администратора WordPress (пароли не передаются в чат). Файлы из комплекта:

| Файл | Назначение | SHA-256 |
|---|---|---|
| `maxbit-theme-0.2.0.zip` | тема MAXBIT (папка `maxbit/`) | см. `dist/SHA256SUMS.txt` |
| `maxbit-core-0.2.0.zip` | модуль MAXBIT Core (папка `maxbit-core/`) | см. `dist/SHA256SUMS.txt` |

Оба ZIP — стандартные устанавливаемые пакеты WordPress: ставятся через панель, без SSH и WP-CLI. Секретов, внутренних документов, клиентских данных, дампов и журналов в них нет (проверено `scripts/build-dist.sh`).

---

## 0. Проверить, что WordPress установлен и работает (5 минут)

1. Откройте `https://dev.maxbitpro.ru/wp-login.php` (или по http, пока нет сертификата). Должна открыться форма входа WordPress.
   - Если открывается мастер установки («Добро пожаловать… Название сайта») — установка не была завершена: пройдите мастер (название `MAXBIT dev`, администратор, почта), **снимите** галочку «Видимость для поисковых систем» (поставьте «Попросить не индексировать»).
   - Если ошибка «Error establishing a database connection» — в ISPmanager → Базы данных проверьте имя/пользователя/пароль и сравните с `wp-config.php` (в файловом менеджере). Не меняйте `wp-config.php`, если не уверены — обратитесь в поддержку.
2. Войдите в панель. Запишите (для себя): версию WordPress (Консоль → Обновления; нужна 6.6+), PHP (Инструменты → Здоровье сайта → Информация → Сервер: должно быть 8.3), наличие `mod_rewrite`/ЧПУ (см. шаг 4).
3. Консоль → Плагины: удалите или оставьте неактивными Akismet и Hello Dolly. Других плагинов не ставьте (второй SEO-плагин запрещён заданием).
4. В ISPmanager → WWW-домены → dev.maxbitpro.ru убедитесь, что **PHP 8.3** и каталог `www/dev.maxbitpro.ru`. Рекомендуется включить для домена **HTTP-авторизацию** (ISPmanager: WWW-домены → Защита/«Доступ по паролю» или через `.htpasswd`) — закрытый стенд важнее `noindex`. Логин/пароль для стенда создайте в панели и передайте проверяющим вне чата.

## 1. Установить модуль MAXBIT Core

Консоль → Плагины → Добавить новый → **Загрузить плагин** → выберите `maxbit-core-0.2.0.zip` → Установить → **Активировать**.

Проверка: в левом меню появились пункты **MAXBIT**, **Решения**, **Проекты**, **Обращения**. Если WordPress пишет «Загрузка запрещена» — в `wp-config.php` стоит `DISALLOW_FILE_MODS`; тогда распакуйте ZIP через файловый менеджер ISPmanager в `www/dev.maxbitpro.ru/wp-content/plugins/` (должна получиться папка `plugins/maxbit-core/maxbit-core.php`) и активируйте в Плагинах.

## 2. Установить тему MAXBIT

Консоль → Внешний вид → Темы → Добавить → **Загрузить тему** → `maxbit-theme-0.2.0.zip` → Установить → **Активировать**.

Порядок важен: сначала модуль, потом тема. (Тема без модуля не падает, но покажет предупреждение администратору; модуль без темы работает с нейтральным оформлением карточек.) Twenty Twenty-Three или другую стандартную тему можно оставить как резервную.

## 3. Настроить среду стенда

1. Консоль → **MAXBIT** (верхний пункт меню). В таблице состояния должно быть:
   - Среда: `staging` — не индексируется, черновики закрыты, внешние отправки выключены;
   - Режим формы: `LOCAL_TEST`;
   - Доставка в Битрикс24: **выключена**; Аналитика: **выключена**; Почта WordPress: **выключена (стенд)**.
   Если вы хотите получать письма (например, сброс пароля) — снимите галочку «Не отправлять письма вне production» и сохраните. По умолчанию письма со стенда не уходят.
2. Блок «Среда стенда»: оставьте `staging`. Значение `production` из панели недоступно намеренно — только константой `MAXBIT_ENV` в `wp-config.php` после приёмки.
3. Настройки → Чтение → поставьте галочку **«Попросить поисковые системы не индексировать сайт»** → Сохранить. (Модуль и так отдаёт `noindex` вне production, но эта галочка — вторая линия.)
4. Настройки → Постоянные ссылки → **Произвольно**: `/praktika/%postname%/` → Сохранить. Если WordPress сообщает, что не может записать `.htaccess`, создайте файл `.htaccess` в корне `www/dev.maxbitpro.ru` с содержимым:
   ```
   # BEGIN WordPress
   <IfModule mod_rewrite.c>
   RewriteEngine On
   RewriteBase /
   RewriteRule ^index\.php$ - [L]
   RewriteCond %{REQUEST_FILENAME} !-f
   RewriteCond %{REQUEST_FILENAME} !-d
   RewriteRule . /index.php [L]
   </IfModule>
   # END WordPress
   ```
   Если на домене только nginx (без Apache) — поддержка Webhost1 должна включить стандартное правило `try_files $uri $uri/ /index.php?$args;`.
5. Настройки → Общие: Название `MAXBIT`, подпись `Системы управления бизнесом`, часовой пояс `Москва`/`UTC+7` по вашему выбору, язык сайта — Русский (если установлен). Настройки → Обсуждение → снять «Разрешить комментарии».

## 4. Наполнить тестовым содержанием

Консоль → **MAXBIT → Наполнение** → кнопка **«Выполнить наполнение»**. На экране появится журнал: `+ создано …` для каждого материала и `Наполнение завершено`.

Что создаётся: главная, «Решения», «Заказ под контролем» (допущено к показу), «Битрикс24 для производственной компании», «Как работаем», «О компании», «Практика» + статья, черновик **ИИ-Практикума** (допуск выключен), 5 пустых черновиков **«Кандидат 1…5»** (имена клиентов в код не включены — переименуйте в редакторе, если нужно), закрытый учебный образец кейса, главное меню и меню подвала.

Правила: повторное нажатие ничего не перезаписывает и не удаляет (материалы ищутся по служебному ключу). Образцы ядра «Привет, мир!» и «Пример страницы» при первом наполнении перемещаются в корзину (не удаляются). Если на этом WordPress уже есть ваше содержание — оно не затрагивается; главная страница назначается только если ещё не назначена.

Если наполнение не стартовало, в адресе получилась ошибка 500 или белый экран — см. раздел 8.

## 6. Что настроено как «dev» и как это потом переключается

| Параметр | На стенде сейчас | Как переключить (после приёмки, отдельное решение) |
|---|---|---|
| Индексирование | запрещено: `noindex`, `robots Disallow /`, sitemap выключен | `define('MAXBIT_ENV','production');` в `wp-config.php` **и** снять галочку в Настройки → Чтение |
| Форма | `LOCAL_TEST`: записи помечены тестовыми, подпись под формой | `define('MAXBIT_FORM_MODE','PRODUCTION');` |
| Доставка в CRM | выключена | с модуля 0.4.0 — вебхук вводится в **MAXBIT → Настройки → Приём заявок** (не в конфиг и не в чат); работает при `MAXBIT_FORM_MODE` ≠ LOCAL_TEST |
| Уведомления о заявке | нет | адреса почты и бот Telegram — в MAXBIT → Настройки; письма уходят от `site@<домен>` (создать ящик/SPF на хостинге) |
| Аналитика | выключена, события в `dataLayer` | номер счётчика Метрики — в MAXBIT → Настройки → Яндекс; подключается только в production; `MAXBIT_ANALYTICS_ENABLED` для событий dataLayer |
| Почта | выключена | галочка в MAXBIT → Среда или production |
| Лимит формы за прокси | автоматически берётся первый адрес `X-Forwarded-For`, если `REMOTE_ADDR` — локальный/частный (nginx→Apache на Webhost1) | при другом прокси — `define('MAXBIT_TRUSTED_PROXY','IP');` |

Все константы добавляются **над** строкой `/* That's all, stop editing! */` в `wp-config.php`. На этом этапе ни одна из них не нужна.

### 6a. Перенос на боевой домен maxbitpro.ru (порядок, модуль ≥ 0.4.0)

0. До переноса: заполнены MAXBIT → Настройки (контакты, реквизиты оператора ПДн, адрес уведомлений, вебхук Б24 при необходимости, счётчик Метрики); политика и согласие проверены юристом; в поддержку Webhost1 отправлено письмо про BitNinja (капча для ботов).
1. Резервная копия dev в ISPmanager (файлы + база).
2. В ISPmanager создать WWW-домен `maxbitpro.ru` (с `www`, HTTPS Let's Encrypt, редирект на https и на домен без www) и новую базу MySQL.
3. Скопировать файлы `www/dev.maxbitpro.ru` → `www/maxbitpro.ru`; импортировать дамп базы dev в новую базу (phpMyAdmin / «Базы данных» в ISPmanager).
4. В `wp-config.php` боевой копии: доступы к новой базе и блок над `/* That's all */`:

```php
define( 'WP_HOME',    'https://maxbitpro.ru' );
define( 'WP_SITEURL', 'https://maxbitpro.ru' );
define( 'MAXBIT_ENV', 'production' );
define( 'MAXBIT_FORM_MODE', 'PRODUCTION' );
define( 'MAXBIT_ANALYTICS_ENABLED', true );
define( 'MAXBIT_MAIL_FROM', 'site@maxbitpro.ru' );   // ящик создан на хостинге, SPF включает Webhost1
```

5. Из админки боевой копии (администратор): `POST /wp-json/maxbit/v1/update/migrate` с `{from:"dev.maxbitpro.ru", to:"maxbitpro.ru"}` — сухой прогон, затем с `confirm:"migrate"`. Адреса в содержимом, настройках и мета меняются на боевые.
6. Настройки → Чтение: снять «Попросить поисковые системы не индексировать». Настройки → Постоянные ссылки → Сохранить (перечитать правила).
7. Проверка: 13 страниц 200, `robots.txt` боевой, `/wp-sitemap.xml` 200, `/llms.txt` 200, нет `dev.` в HTML, canonical/og:url/JSON-LD на боевом домене, `curl -A YandexBot` → 200, тестовая заявка → письмо + лид в Б24 → удалить.
8. Dev остаётся staging (noindex); при желании закрыть HTTP-паролем в ISPmanager.
9. Вебмастер/Метрика/Бизнес/Bing/GSC — коды через MAXBIT → Настройки, sitemap отправить вручную.

## 7. Обновление сборки в будущем

Новая версия темы/модуля ставится теми же ZIP: Плагины → Добавить → Загрузить → WordPress предложит «Заменить текущую версию загруженной». Содержание в базе не затрагивается. Перед обновлением — резервная копия через ISPmanager (файлы + база).

С модуля 0.3.2 есть путь без ручной загрузки — один запрос из админки (администратор, залогинен):
`POST /wp-json/maxbit/v1/update/fetch` с телом `{url, sha256, type: theme|plugin}` — сервер скачивает ZIP по https-ссылке, сверяет SHA-256, делает копию текущей версии в `wp-content/maxbit-backups/` (5 последних) и ставит. Готовый JS печатает `scripts/deploy-package.py <zip> --type theme --fetch-url https://… --emit-js`. Ссылка должна быть публичной прямой (GitHub Releases, Яндекс.Диск «прямая ссылка» и т. п.); пакет до 20 МБ. `POST …/update/cleanup` убирает остатки прерванных передач, `GET …/update/status` показывает версии, копии и остатки. База не изменяется; наполнение — только отдельным `POST …/update/seed`.

## 8. Если что-то пошло не так

- **Белый экран / «критическая ошибка»** после активации: в ISPmanager включите отображение ошибок PHP или откройте `wp-content/debug.log` (если `WP_DEBUG_LOG` включён). Деактивировать плагин без панели — переименовать папку `wp-content/plugins/maxbit-core` в `maxbit-core.off`; тему — переименовать `wp-content/themes/maxbit` (WordPress переключится на резервную).
- **Адреса `/praktika/…` дают 404** — не применились ЧПУ: Настройки → Постоянные ссылки → Сохранить ещё раз; проверьте `.htaccess`/nginx (шаг 3.4).
- **Форма отвечает «Слишком много попыток»** — сработал лимит 5 за 10 минут с одного адреса. Если это происходит у разных людей сразу — сервер не передаёт реальный адрес (см. таблицу в разделе 6, `MAXBIT_TRUSTED_PROXY`).
- **Письма не приходят** — так задумано на стенде; см. раздел 3.1.
- **Нужно откатить наполнение** — удалите созданные материалы через Корзину (они помечены служебным ключом `_mb_seed_key`); повторное наполнение создаст их заново.

## 9. Что не входит в эту инструкцию

Домен, DNS, сертификат (поддержка Webhost1); реальные контакты и тексты (решения владельца, OPEN_ITEMS §1); подключение CRM, аналитики, юридические тексты, резервное копирование и мониторинг (условия публичного выпуска, docs/02 §3).
